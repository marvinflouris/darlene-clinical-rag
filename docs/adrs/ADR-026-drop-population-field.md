# ADR-026: Drop population from the chunk metadata
- Date: 2026-11-08
- Status: accepted. Partly replaces ADR-012.
- Context: The population field was added after the 30 expert questions showed that nearly every question names an age group, pregnancy or HIV status. Checked against the book, only 53 of the 477 condition titles in the first condition list (11%) name a patient group. For all the others the field would say 'not stated'. A single chunk can also span groups: the adrenaline line holds both adult and child doses. Where the group matters, it is already in the condition title (Pneumonia in an Infant up to 2 months, in a Child of 2 months-5 years, in Children over 5 years and adults) or in the chunk text (age lines, table columns such as pregnancy trimester). No pipeline step uses the field, because the condition resolver reads the condition list.
- Options considered: (a) keep population as a chunk field; (b) drop it from chunks and keep a population hint in the condition list; (c) fill it from the lines inside each chunk.
- Decision: (b). The condition list keeps the population_hint_from_title column for the resolver. Population information in chunks stays in condition_title and in the text.
- Why: Where the field is filled it repeats condition_title. Elsewhere it says nothing. It cannot describe a chunk that spans groups. ADR-012's test is that a step must use a field, and none does. Option (c) would risk wrong values in a medical source (see ADR-013).
- Consequences: Chunks have 17 metadata fields. The Identity group has five: condition_id, condition_title, parent_condition_id, icd10, order_in_condition. If Stage 3 tests show that patient-group ranking needs a field, a script can add one later from the titles or the text, without re-chunking.
